What is measured?

These runs measure how long HOL Light takes to load and check several large proof developments. Each theorem is reconstructed through the HOL Light kernel. The archive contains four benchmark families and five result files because s2n-bignum records ARM and x86 separately.

The reports record source commits and machine information. Those fields matter: a timing comparison is most useful when the proof sources, CPU, architecture, memory, and level of parallelism are comparable.

HOL Light regression suite

HOL Light includes holtest.mk, a broad regression suite covering its libraries, examples, decision procedures, formalized mathematics, and supported external tools.

The runner executes independent test targets concurrently. Each test has its own log and timing. A test may be skipped when an optional external program is unavailable; the archived runs normally skip the legacy zChaff/MiniSat-p test.

s2n-bignum: ARM and x86

s2n-bignum contains optimized assembly routines for cryptographic big-integer arithmetic, together with HOL Light proofs of functional correctness and related safety properties.

ARM and x86 are separate reports. The runner assembles each architecture's source and checks the proof against the resulting object code. Foreign machine code is not executed, so the non-native architecture only needs a cross-assembler rather than an emulator. Proof binaries are built and checked concurrently with a memory-based job limit.

Flyspeck

Flyspeck is the formal proof of the Kepler conjecture. The benchmark loads load_flyspeck.ml and evaluates the complete Build.build_sequence_full.

The run verifies the archived linear-program certificates and loads the text formalization. The nonlinear inequalities are imported against recorded digests rather than recomputed; their original recomputation required a large external Azure workload. The tame-hypermap classification is verified separately in Isabelle, as documented by Flyspeck.

Four Colour Theorem

HOL Light's 4CT/ development proves the Four Colour Theorem for hypermaps, planar graphs, and plane maps.

The benchmark uses the OCaml 5 parallel bytecode route. Its proof-producing computations distribute the presentation checks and 633 reducibility checks over as many as 128 OCaml domains. A successful report contains FOUR_COLOR, FOUR_COLOR_PLANAR_GRAPH, and FOUR_COLOR_MAP.

Result statuses

Pass
The target completed and no applicable failure marker was found.
Fail
The target stopped early, emitted a proof/load error, or did not reach its required completion theorem or marker.
Skip
The suite deliberately omitted a test because an optional dependency was unavailable.
Missing
No complete output was produced, usually because a run was interrupted.

Failure markers are case-insensitive log lines such as error:, exception:, and Error in included file; ### Error: skip is excluded. Holtest also requires a .ready file, while Flyspeck and 4CT require their completion markers and 4CT's final theorem bindings. See common/check-failures.sh for the shared marker rules.

How to read timings

Individual elapsed times are wall-clock durations reported by each test or proof. A report's total is the sum of those individual durations, not necessarily the wall time of the parallel suite.

The comparison page defines speed ratio as baseline time / comparison time. A value above 1.0× means the comparison is faster. Average improvement is based on the geometric mean of individual speed ratios, so proportional changes in short and long tests receive equal weight.

Run the benchmarks

Setup instructions and runners are available in the benchmark-scripts repository. Its run-all.sh creates a fresh HOL Light workspace, runs every suite, and writes reports in the format consumed by this site.
